# FIGMA-SYNC.md

「Storybook と Figma を同期して」と指示されたときに読む設定とルールです。
ここに書いてある値は確認せずにそのまま使ってください。書いていない事項や、判断に迷う事項だけユーザーに確認します。

> **使い方**：リポジトリのルートに置き、`（要入力）` の箇所をプロジェクトに合わせて書き換えてください。「6. 同期履歴」と「7. 未決事項・追加要件メモ」は同期作業のたびに AI が更新します。

## 1. 同期先

| 項目               | 値                                                                        |
| ------------------ | ------------------------------------------------------------------------- |
| Figma ファイル URL | （要入力）例：`https://www.figma.com/design/<fileKey>/<fileName>`         |
| fileKey            | （要入力）URL の `/design/` の直後の文字列                                |
| 書き込み先ページ   | （要入力）例：`Components`（なければ作成してよい）                        |
| 変数の管理場所     | （要入力）例：同ファイル内のローカル変数／ライブラリファイル              |
| MCP サーバー       | Figma MCP（`plugin:figma:figma`、リモート版 `https://mcp.figma.com/mcp`） |
| Figma アカウント   | （要入力）例：チーム名・プラン（Starter / Professional など）・シート種別 |

- 書き込み先ページ以外のページ・フレームは変更しない
- fileKey が未記入の場合だけ、ユーザーに URL を確認する

### MCP の使い方

- 最初に `create_session`（fileKey とタスク概要）を呼び、返ってきた sessionId を以降の呼び出しで使い回す
- `use_figma` の前に `/figma-use` と `/figma-generate-library` スキルを読み込む
- ツール呼び出し回数を最小にする（読み取りはまとめて 1 回で済ませる、1 回の `use_figma` で複数ノードを作るなど）。上限に達した場合は作業を止めて報告する。**Starter プランは上限が特に厳しい**
- Starter プランでは変数コレクションのモードが 1 つまでしか作れない（`addMode` が `Limited to 1 modes only` で失敗する）。その場合、light / dark などはモードではなくグループで分ける（3.3 参照）
- MCP はクラウド上で動くため、ローカルにだけインストールしたフォントは読み込めない。その場合はテキストスタイルを仮フォントで作り、Figma デスクトップでスタイルのフォントだけを差し替える
- `get_screenshot` の画像は curl でダウンロードせず、`enableBase64Response: true` で直接受け取る

## 3. 命名・構造のルール

### 3.1 コンポーネント名

- ストーリーの `title` から `Components/` を除いた名前を Figma のコンポーネント名にする
  - 例：`title: 'Components/Button'` → `Button`
  - 階層が深い場合（`Components/Form/Input`）は `Form/Input` のスラッシュ区切りにする
- コード側のコンポーネント名（PascalCase）と一致させる

### 3.2 props → Figma プロパティ

| コード側（`args` / `argTypes`）                        | Figma 側                                 |
| ------------------------------------------------------ | ---------------------------------------- |
| 選択肢が決まった props（union 型、`options` 指定あり） | バリアントプロパティ                     |
| 見た目が変わる boolean（例：`disabled`）               | バリアントプロパティ（`true` / `false`） |
| 表示テキスト（`children`、`label` など）               | テキストプロパティ                       |
| アイコンなど差し替え可能な要素                         | インスタンス切り替えプロパティ           |
| レイアウトだけが変わる boolean（例：`fullWidth`）      | 対象外（リサイズ設定 Fill / Hug で表現） |
| イベントハンドラ（`onClick`）、`href`、`target` など   | 対象外                                   |

- プロパティ名・値はコードの props 名・値をそのまま使う（キャメルケースのまま、翻訳・言い換えをしない）
- ホバーなど CSS の擬似クラスで表す状態は、バリアント `state`（`default` / `hover`）として追加してよい
- バリアントの組み合わせが 24 通り以上になる場合は、作成前に絞り込み案を提示する

### 3.3 変数・スタイル

同期元のファイルと、Figma 側の変数コレクションの対応です。

| 同期元                                     | Figma 変数コレクション | 変数名の例 |
| ------------------------------------------ | ---------------------- | ---------- |
| （要入力：例 `src/styles/colors.css`）     | （要入力：例 `color`） |            |
| （要入力：例 `src/styles/tokens.css`）     | （要入力：例 `space`） |            |

- モード：（要入力：例 `light` / `dark` の 2 モード。Starter プランの場合は `value` の 1 モードにし、`light/`・`dark/` のグループに同じ名前で登録してコンポーネントには `light/` を紐付ける）
- 変数名は CSS カスタムプロパティ名から `--` を除いたもの。同じ値への参照（エイリアス）は別の変数を作らない
- Figma の変数名には `.` が使えないので、`1.5` のような値は `1_5` と書く
- コードに CSS 変数がない派生色は、コード側の式を code syntax に書いて変数にする
- テキストスタイル・エフェクトスタイル：（要入力：例 `text-sm`（14/20）、`shadow-lg`）
- 色がコード側で `oklch()` などで書かれている場合は、sRGB に変換して登録する
- `clamp()` などで可変の値は、（要入力：例 PC 値（1280px 時））で登録する
- Figma ファイルにすでにある変数・スタイルを優先して使う。対応する変数がない場合は、作成前に変数名と値の案を提示して確認する
- コンポーネント内で色・余白の値を直書きしない（変数にバインドする）
- フォント：（要入力：例 `Inter`）。MCP から読めない場合はテキストスタイルを仮フォントで作り、代替したことを結果報告に書く

### 3.4 レイアウト

- コンポーネントはオートレイアウトで組む
- 余白・間隔・角丸は、コンポーネントのスタイル（CSS・Tailwind クラスなど）から値を読み取って一致させる
- レイヤー名は意味のある名前にする（`Frame 12` のような自動命名を残さない）

## 4. 同期の進め方

1. 同期対象のストーリーを一覧化する（ストーリーファイルとコンポーネント本体の両方を読み、props とスタイルを把握する）
2. Figma の書き込み先ページと変数を読み取り、既存コンポーネントと照合する（「6. 同期履歴」のノード ID を使う）
3. 各コンポーネントを次のいずれかに分類し、同期計画として提示する
   - **新規作成**：Figma にない
   - **更新**：Figma にあり、props・スタイルに差分がある
   - **変更なし**：差分がない
4. 承認を得てから Figma に書き込む
5. 書き込み後に `get_screenshot` で見た目を確認し、Storybook の表示（要入力：例 `pnpm storybook` で起動してスクリーンショットを撮る）と見比べる
6. 結果を報告し、「6. 同期履歴」を更新する

## 5. 禁止事項・注意事項

- Figma 上のコンポーネントを削除しない（コード側で削除されたものは報告だけする）
- バリアントの削除やプロパティ名の変更など、既存インスタンスに影響する変更は必ず事前に確認する
- 同期対象外のページ・コンポーネントを変更しない
- 機密情報・非公開情報（要入力：該当するディレクトリなどがあれば書く）をサンプルテキストに使わない。サンプルテキストはストーリーの `args` の値を使う
- コード側（コンポーネント・ストーリー）は同期作業では変更しない。差分を見つけたら報告だけする
