# Design System Setup

既存の Web アプリケーションのリポジトリを pnpm ワークスペースのモノレポに組み替え、デザインシステム（packages）とデザインハーネスの枠をセットアップするための AI 向け指示書です。

[DESIGN_SYSTEM_SETUP.md](DESIGN_SYSTEM_SETUP.md) をリポジトリに置き、Claude Code などのコーディングエージェントにフェーズごとに指示すると、環境調査から移設、パッケージ作成、境界ルール・CI の整備までを同じ手順で進めてくれます。

## できあがるもの

```
<repo>/
├─ packages/
│  ├─ tokens/          # すべての値の正（DTCG 形式 JSON → CSS 変数・TS 定数・Figma 用 JSON）
│  ├─ brand/           # ロゴ・フォント・画像のトーンなど、媒体を問わないブランドの核
│  ├─ design-system/   # プロダクト UI 用の React コンポーネント
│  ├─ communication/   # スライド・広告バナーの型
│  └─ guidelines/      # コンポーネントをまたぐルール（MDX）
└─ apps/
   ├─ website/         # 既存アプリを移設したもの
   ├─ storybook/       # デザインシステム用カタログ
   ├─ docs/            # 人向けドキュメントサイト（枠のみ）
   └─ harness/         # デザインハーネス（枠と最小限の検査のみ）
```

- ガイドラインは人も AI も同じ MDX を読みます。人向けと AI 向けでドキュメントを二重管理しません
- Claude Design へ「Product UI」と「Brand & Communication」の 2 つのデザインシステムとして同期できる構成になります
- パッケージ間の依存の向きを lint で強制するため、後から `packages/` と `apps/storybook`・`apps/docs`・`apps/harness` を専用リポジトリへ切り出せます

## 前提条件

次の 3 つは必須です。

- **既存アプリが React を使っていること**
  - Next.js（App Router／Pages Router）と Vite + React が標準対応です。Remix や Astro + React などは、調査レポートで注意点を確認したうえで対応します
  - Vue、Svelte、Angular など React 以外の場合は、エージェントが作業を止めて報告します
- **作業ツリーにコミットされていない変更がなく、既存アプリのビルドが通ること**
  - 移設の前後で結果を比較するためです。どちらかに当てはまらない場合、エージェントは作業を止めます
- **ファイル操作とコマンド実行ができるコーディングエージェントを使うこと**
  - Claude Code、Codex、Cursor など

次の点は事前に決めておく必要はありません。フェーズ 0 の環境調査でエージェントが判定し、構成案として提示します。

- フレームワーク、スタイリング手法（Tailwind v4／v3、CSS Modules、CSS-in-JS）、lint の設定形式、デプロイ先
- パッケージマネージャ（pnpm 以外の場合は pnpm への移行を提案されます。既存のものを使い続けることもできます）

## セットアップ手順

### 1. DESIGN_SYSTEM_SETUP.md をリポジトリに置く

[DESIGN_SYSTEM_SETUP.md](DESIGN_SYSTEM_SETUP.md) を、対象リポジトリの `docs/design-system-setup.md` としてコピーします。場所は任意ですが、変える場合は以下の指示文のパスも合わせてください。

### 2. 作業用のブランチを作る

エージェントは既定ブランチへ直接コミットしません。`chore/design-system-setup` などのブランチを用意しておくと、そのまま作業に入れます。

## 使い方

1 回の指示で 1 フェーズずつ進めます。各フェーズの最後にエージェントが完了レポート（実施内容、変更ファイル、受け入れ基準の合否、未解決事項）を出すので、内容を確認してから次へ進みます。

| 手順 | 指示文の例 | 成果物 |
| --- | --- | --- |
| 1 | `docs/design-system-setup.md` を読み、フェーズ0（環境調査）を実行して調査レポートを出してください。ファイルは変更しないでください。 | 調査レポート、構成案、変数の決定案 |
| 2 | 調査レポートの内容で確定します。フェーズ1を実行してください。 | 既存アプリの `apps/website` への移設 |
| 3 | フェーズ2を実行してください。 | `packages/` 配下 5 パッケージ |
| 4 | フェーズ3を実行してください。 | `apps/storybook`、`apps/docs`、`apps/harness` |
| 5 | フェーズ4を実行してください。 | 境界ルール、検査スクリプト、CI |
| 6 | フェーズ5を実行してください。 | 最終確認レポート、手動作業の手順書 |

手順 1 の調査レポートは必ず自分で確認してください。特に「変数の決定案」（パッケージのスコープ名など）と「移設計画」（`apps/website` へ移すもの・ルートに残すもの）は後から変えにくいので、変更したい点があれば手順 2 の指示文で伝えます。

途中で中断しても、どこまで完了したかは完了レポートとコミット（先頭に `[design-system-setup phase N]` が付きます）で判断できます。

## 人が行う作業

エージェントは次の作業をおこないません。フェーズ 5 で手順書が出力されるので、それに従って作業してください。

- デプロイ先の設定変更（Vercel の Root Directory を `apps/website` にするなど）
- ブランチのマージと、マージ後の確認
- Claude Design への同期（Claude Code の `/design-sync` で取り込む想定です）

## この指示書で扱わないこと

- コンポーネントの網羅的な実装、ガイドライン本文の執筆（サンプル実装とプレースホルダのみ作成します）
- ハーネスの中身（生成・レビュー・評価のロジック）の実装
- npm への公開、専用リポジトリへの切り出し
